环境配置(Linux)

安装编译器sdcc

引用：SDCC (Small Device C Compiler) 是一个支持 C89/C99/C11/C23 标准的 C 编译器套件，主要支持 8051/Z80/STM8/6502/HC08 等架构

1. 源码编译安装

前往官网下载源码包download

解压后进行编译，因为sdcc是一个通用的编译器, 支持多个平台, 我只需要51系列的, 所以其他平台的直接禁用了, 配置过程缺少依赖库之类的按照错误信息下载就好了

CC=clang CXX=clang++ \
./configure \
  --prefix=$HOME/opt/sdcc/ \
  --disable-z80-port \
  --disable-z180-port \
  --disable-r2k-port \
  --disable-r2ka-port \
  --disable-r3ka-port \
  --disable-sm83-port \
  --disable-tlcs90-port \
  --disable-ez80_z80-port \
  --disable-z80n-port \
  --disable-r800-port \
  --disable-ds390-port \
  --disable-ds400-port \
  --disable-pic14-port \
  --disable-pic16-port \
  --disable-hc08-port \
  --disable-s08-port \
  --disable-stm8-port \
  --disable-pdk13-port \
  --disable-pdk14-port \
  --disable-pdk15-port \
  --disable-mos6502-port \
  --disable-mos65c02-port \
  --disable-f8-port

make -j$(nproc)

make install

2. 包管理器安装

# 以ubuntu为例
apt install sdcc

安装烧录工具stcgal

引用：stcgal是用于[STC MCU Ltd]的命令行闪存编程工具，兼容8051微控制器。STC微控制器具有基于UART/USB的引导加载程序（BSL）。它采用系统内编程，即基于数据包的协议通过串行链路刷新代码存储器和IAP存储器。

需要安装python和pip，然后在用pip安装stcgal即可

pip install stcgal

访问设备串口

引用：CH341 是南京沁恒微电子推出的一款 USB 转串口/并口/I2C/SPI 等多功能接口芯片，通常是USB 转 TTL 串口（UART），用于开发板与电脑通信

检查ch341驱动

运行下面的命令，查看已加载模块列表是否有ch341驱动：

lsmod | grep ch341

如果没有输出，应该是缺少ch341驱动，需要手动加载（linux系统自带ch341驱动）：

modprobe usbserial
modprobe ch341

将开发板的usb线接入电脑后，linux会将其抽象为一个串口文件，通常是/dev/ttyUSB0，具体可以通过查看系统日志dmesg -w来确定文件名，如下所示：

[3169272.084366] ch341 3-9.2:1.0: ch341-uart converter detected
[3169272.085505] usb 3-9.2: ch341-uart converter now attached to ttyUSB0

驱动冲突

如果日志中出现brltty, disconnected等字段，那可能是brltty驱动与ch341驱动冲突了，卸载brltty驱动即可

[3168735.065367] input: PC Speaker as /devices/platform/pcspkr/input/input43
[3168735.579503] input: BRLTTY 6.6 Linux Screen Driver Keyboard as /devices/virtual/input/input44
[3168735.676377] usb 3-9.2: usbfs: interface 0 claimed by ch341 while 'brltty' sets config #1
[3168735.677058] ch341-uart ttyUSB0: ch341-uart converter now disconnected from ttyUSB0
[3168735.677079] ch341 3-9.2:1.0: device disconnected

增加串口文件读写权限

找到串口文件后，还需要给文件增加读写权限（因为我们要烧录程序，即向这个串口文件写数据）

chmod 666 /dev/ttyUSB0

验证

以下测试程序会点亮4个LED灯：

/* main.c */

#include "8052.h"

void main(void)
{
    P2 = 0xf0; // 点亮4个led灯
    while (1)
        ;
}

编译烧录命令：

sdcc -o main.ihx main.c         # 编译 （C 代码 → 单片机固件）
packihx main.ihx > main.hex     # 打包/格式化 （优化固件格式）
stcgal -p /dev/ttyUSB0 main.hex # 烧录 （写入单片机）

执行完命令后会出现这样的信息, 我们断电在上电, stcgal就能够烧录程序了

LED模块

电路图中，LED正极接VCC，即正极为高电平，负极为低电平时形成电势差，LED点亮。所以想让LED点亮，就往负极输入低电平，从软件角度来看就是向对应的引脚写入0（正极到电源之间接的是限流电阻，防止直接连接电源导致电流过大，烧毁LED）

以D1为例，他接的是P20引脚，所以向P20写0时，D1就被点亮。以下示例程序会点亮D1-D4：

#include "8052.h"
void main(void)
{
               /* P27 P26 P25 P24 P23 P22 P21 P20 */
               /* D8  D7  D6  D5  D4  D3  D2  D1  */
    P2 = 0xf0; /* 1   1   1   1   0   0   0   0   */
    while (1)
        ;
}

独立按键

单片机上电时，所有引脚都是高电平，即都是1，独立按键初始时是松开状态，推导过来就是独立按键松开状态时连接的引脚是高电平。简单来说就是，独立按键按下时会向引脚写0,松开时会向引脚写1。所以可以通过监控引脚的值来判断按键的状态

但是按键属于机械按键，按下松开时会有回弹的情况，会造成按键抖动，以一个按键状态变化（图中是按下）的周期为例：

  1. 开始时，按键为松开状态（稳定）
  2. 按下按键，因为按键回弹会使得按键在松开和按压之间抖动（不稳定）
  3. 过一小会后，按键状态稳定，处于按压状态（稳定）
  4. 松开按键，因为按键回弹会使得按键在松开和按压之间抖动（不稳定）
  5. 过一小会后，按键状态稳定，处于松开状态（稳定）

在这个按键变化周期中，按键理论上状态变化了两次（1 -> 0 -> 1），但实际上因为抖动的影响，状态变化会有多次。考虑以下代码：

while (1) {
    if (P32 == 0)
        P20 = 1;
    else
        P20 = 0;
}

代码很简单，按下K3，D1亮，松开K3，D1灭。理论上，快速的点按K3，D1应该是先亮后灭，即闪烁一下。但因为抖动的存在，状态变化更多次，所以即使是点按，也可能让D1闪烁多次（人眼可能无法区分）。正确的写法，是主动延迟一定时间，消除抖动后在执行具体的逻辑：

while (1) {
    if (P32 == 0) {         /* 触发条件 */
        delay();            /* 消除 1 - 0 的抖动 */
        while (P32 == 0)    /* 度过按键状态稳定时期  */
            ;
        delay();            /* 消除 0 - 1 的抖动 */
        /* 至此，按键点按的一个周期消耗完毕，在执行按键点按后该有的逻辑 */
        P20 = 1;
    } else
        P20 = 0;
}
